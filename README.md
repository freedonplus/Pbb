> 一个会先问你 7 轮问题、再给出可落地生产级后端方案的 Skill。不是技术栈清单生成器。
>
> **v2**：审核清单扩到 384 条，新增多语言八股底稿、AI 辅助编码治理与网络安全保障；不再承诺「零故障」，只承诺能证明、能发现、能止损。

## 它解决什么问题

让 AI「设计一个生产级后端」，通常得到两种结果：一份把所有中间件都堆上的清单，或者一篇复述八股的文章。两者都不能用，因为**生产级不是「全都做」，而是「每个业务域为哪些能力付出工程成本」**。

这个 Skill 换了个做法：

1. **先问**。规模多大、有没有写热点、要不要接支付、谁来做前端 —— 答案不同，方案差三倍。
2. **再推导**。每个答案对应明确的技术决策规则（锁用哪种、缓存三害怎么治、MQ 选谁、要不要分片），规则写在仓库里，可审计。
3. **最后写方案**。按 12 章八股骨架输出，每条决策都带「选择 / 理由 / 否决项」，而不是只给结论。

## 它不是

- 不是代码生成器：只产出方案文档，不写业务代码。
- 不是前端脚手架：**后端交付到接口 + 契约文档为止**，不碰前端页面、不改前端仓库。
- 不是万能模板：不确定的地方它会追问，而不是编一个默认值。

## 先判场景，再决定做什么

不是所有请求都该从提问开始。技能第一步先判三种场景：

| 场景 | 触发信号 | 行为 |
| --- | --- | --- |
| **A. 已有项目 · 没按本技能设计** | 有代码，但找不到方案书 / API 契约 / 错误码表 | 差距检查 → 输出「差距 + 建议」，**改不改由你决定**，不动你的代码 |
| **B. 已有项目 · 本技能产出** | 方案书首行有 `blueprint-meta` 指纹；或无指纹但基线三件套有其二（方案书 / OpenAPI / 错误码表） | 审核模式：按 384 条清单逐项出报告，分阻断 / 建议 / 记录三级 |
| **C. 无项目 · 计划新建** | 只有一个想法 | 7 轮提问 → 12 章方案 → 检阅迭代 |

场景 A 和 B 的分界是**有没有基线**：有基线才能说「你没按方案做」，没基线只能说「这里是差距」。

## 工作流

```
场景判定 ─┬─ C 无项目 ──→ 语言判定 → 7 轮提问（每轮 ≤4 问，带推荐项）
          │            → 决策回执表（问题 → 你的选择 → 推导结论）← 你确认
          │            → 12 章方案（Markdown 落盘，present 给你）
          │            → 你检阅 → 局部修订 → 定稿 → 问是否进入实施
          │
          ├─ B 有基线 ──→ 读方案书 + OpenAPI + 错误码表建基线
          │            → 声明覆盖率（>200 个类先跑结构性 grep 扫描，再定点读）
          │            → 逐组过 384 条清单（通用 A–AD 30 组 / 攻击面 6 组 / 语言 / 中间件）
          │            → 每条带稳定 ID + 证据（文件:行）+ 四态判定 + 证据分层（静态 / 运行 / 生产）
          │            → 审核报告（走结论门禁）→ 你选要整改的项 → 按阻断优先处理
          │            → 整改后阶段 5 复评：按 ID diff 出 v2 报告
          │
          └─ A 无基线 ──→ 抽关键组比对 → 差距 + 建议 → 你自行决定
```

审核期间只做**偏差登记**，不擅自改文档：发现实现与方案不一致，先进报告「偏差登记」节，你确认后才回写方案书与 OpenAPI，并在变更记录留痕。

报告必须声明两条口径：**覆盖率**（已核查 m / 384，通过率分母只用已核查项）与**边界**（静态审核不等于渗透测试，不构成安全保证）。

### 7 轮提问速览

| 轮次 | 主题 | 关键问题 |
| --- | --- | --- |
| 1 | 规模与架构 | 语言生态、中小/中大/大型、简单单体 / 多模块单体 / 微服务、流量模型 |
| 2 | 框架与版本 | 语言版本与框架版本是否匹配、是否用快速开发框架（RuoYi / JeecgBoot / Go-Zero）、构建方式 |
| 3 | 数据层 | 数据库选型、ORM、**分库分表（不分 / 垂直 / 水平 + 阈值）**、ES 与对象存储 |
| 4 | 中间件与异步 | Redis、**MQ 选型（RabbitMQ / RocketMQ / Kafka / 不需要）**、定时任务、部署形态 |
| 5 | 业务风险面 | **有无写热点**（决定分布式锁 / 乐观锁 / 悲观锁）、是否接支付、第三方（微信等）、哪些操作要幂等 |
| 6 | 安全与合规 | 认证方案（Sa-Token / Spring Security / JWT+Casbin）、敏感字段、接口防护等级、等保/GDPR |
| 7 | 交付与协作 | **API 文档方案**、前端联调方式、**前后端边界确认** |

回答会被用来裁剪后续问题：选了「纯内部工具」就跳过支付轮，选了「无写热点」就不硬塞分布式锁。

### 输出：11 章骨架 + 版本页

```
〇、版本与变更记录          六、中间件与异步
一、项目概述与规模评估      七、高并发与一致性设计
二、架构选型                八、幂等与事务
三、技术栈清单              九、安全体系
四、项目结构                十、接口契约与文档
五、数据设计                十一、生产保障
                            十二、落地优先级与风险
```

其中：

- 第五章必须含**索引设计表**（查询场景 → 索引列序 → 类型 → 理由）与索引失效自查；第六章必须含**缓存决策矩阵**（哪些数据用缓存、哪些坚决不用，逐对象给理由）。
- 第七章必须给出锁粒度、缓存三害方案、限流三档阈值、熔断降级、容量估算（带假设算式）。
- 第九章必须含威胁建模与 Abuse Case、**核心业务不变量**（代码 + DB 约束 + 反例/并发/重放测试 + 对账告警四层）、AI 变更防篡改、C1–C4 人工放行、网络与运行时防护、入侵响应。
- 第十章是**对前端的正式交付物**：OpenAPI 方案、统一响应体、错误码分段、时间/金额/ID 字段规范、鉴权约定、`Idempotency-Key`、可导出导入 Apifox/Postman。
- 第十二章用「业务域 × 能力矩阵」（缓存/锁/幂等/加密/脱敏/限流/异步/审计）自证取舍，再给 P0/P1/P2 清单与「不做的事」。

## 三条硬规则

这三条是写进 Skill 的强制约束，不是建议：

### 1. API 文档是交付物，不是附属品

对接前端必须有机器可读契约：文档与代码同源（注解/装饰器生成），可导出 OpenAPI JSON，可直接导入 Apifox / Postman；生产环境关闭文档端点或加鉴权。禁止手写一份与代码脱节的 Word。

### 2. 后端不插手前端

后端交付边界：**接口 + 契约文档 + 错误码表 + 示例**。

- 不写前端页面/组件，不改前端仓库，不替前端决定交互与状态管理。
- 前端提出的字段/接口诉求，在契约层解决（加字段、扩枚举、加接口），不让前端拼数据迁就后端缺陷。
- 跨域白名单与登录态**配置**是后端责任；Token 怎么存由前端决定。
- 本质属于前端的诉求（渲染、交互、路由），记录为「前端侧需求」交回，不展开实现。

---

### 3. AI 不能自己给自己放行

AI 写的代码默认不可信。C3（权限、支付退款、资金库存、密钥、敏感数据、DB 迁移）与 C4（CI/CD、CODEOWNERS、生产 IAM/网络、签名制品、不可逆操作）必须由**独立的人在独立证据上签字**：

- AI 无主干直推权、无长期生产权限，不得自审、自合并、自发布，也不得修改 CODEOWNERS / 分支保护 / 扫描阈值来放行自己。
- 第二个模型复审仍然**不算**人工审核；检查全绿**不算**安全证明。
- C3/C4 缺放行单，直接判 **P0：不可上线（流程阻断）**。
- 禁止输出「保证上线不出问题」；只声明验证范围、未覆盖项、残余风险与止损能力（灰度、kill switch、可信回滚制品、不可变备份、应急 Runbook）。

## 安装

WorkBuddy 的用户级 Skill 目录：

```bash
# macOS / Linux
cp -r prod-backend-blueprint ~/.workbuddy/skills/

# Windows (Git Bash)
cp -r prod-backend-blueprint "$USERPROFILE/.workbuddy/skills/"
```

**Skill 在会话启动时加载**，装完需要新开一个会话才会出现在可用列表里。

触发方式（说人话即可，不必念名字）：

> 我要做一个旅游电商的后端，按生产级来规划
> 帮我评估下这个项目该用单体还是微服务
> 生产环境后端架构选型，Java 的

## 覆盖的决策点

| 主题 | 覆盖内容 |
| --- | --- |
| 架构 | 单体 / 多模块单体（app + common + 业务模块）/ 微服务，含演进路径与拆分触发条件 |
| 数据 | 库选型、ORM、索引、**分库分表（垂直/水平 + 单表行数阈值）**、读写分离、迁移工具 |
| 并发 | 分布式锁（Redisson）、乐观锁条件更新、悲观锁、秒杀预扣 + MQ 削峰、线程池隔离 |
| 缓存 | **缓存决策矩阵**（哪些不用缓存：强一致源数据 / 写多读少 / 低频 / 大列表）、穿透击穿雪崩、TTL 抖动、逻辑过期、多级缓存、一致性策略 |
| 索引 | **索引设计表**、最左前缀、覆盖索引、索引下推、五类失效场景、回表成本、大表 DDL（gh-ost/pt-osc）、隐藏索引灰度下线 |
| 幂等 | 创建类（Idempotency-Key + SETNX）、支付回调、状态机、MQ 消费、防重放 |
| 异步 | RabbitMQ / RocketMQ / Kafka 选型依据、事务消息、延迟消息、死信、消费幂等 |
| 安全 | 密码 BCrypt、字段 AES-256-GCM + 盲索引、脱敏、密钥外置与轮换约束、高危接口加签、限流、审计 |
| 契约 | OpenAPI、统一响应体、错误码表、字段规范（时间/金额/ID）、版本管理、导入导出 |
| 上线 | 优雅停机、readiness、备份**演练**、灰度回滚、DDL 与发布解耦、依赖 CVE、日志留存 |
| 语言陷阱 | Java `BigDecimal`/字符串拼接/包装类缓存/JVM GC 选型、JS 双精度、Go `float64`、Python `decimal`、PHP 类型 juggling、C# `decimal`/`async void`、Rust `unwrap`/取消安全、时区统一 |
| AI 与安全 | Prompt Injection 防护、AI 最小权限与发布链防篡改、SBOM/provenance/制品签名、核心业务不变量四层保护、C1–C4 人工放行、威胁建模与 Abuse Case、DAST/Fuzz、WAF 与网络分段、入侵响应 Runbook |

## 支持的语言体系

方案骨架：Java / Spring（最完整）｜Go（Gin / Go-Zero / Kratos）｜Python（FastAPI / Django）｜Node（NestJS）。
骨架对四者同构（架构 → 分层 → 数据 → 中间件 → 并发 → 安全 → 可观测 → 契约），差异点单列在 `references/stacks/`，八股与生产陷阱看 `bagu-essentials.md` 与 `bagu-polyglot.md`（含 PHP / C# / Rust）。

审核清单额外覆盖：C# / .NET、PHP、Rust、SQL 通用规范，以及 MySQL / Redis / Kafka·RabbitMQ·RocketMQ / Nginx / Docker / Kubernetes 六类中间件小节；语言无 stacks 基线时显式声明并强制查官方文档核对版本，不凭记忆编依赖。
