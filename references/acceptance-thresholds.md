# 合格线阈值表（把「是否」变成「对不对」）

> 配套 `verification-standard.md` 使用。本表为**常见行业基线**，不是唯一正确答案。
> 项目可调，但必须书面声明调整项、调整理由与签字人（规则见 verification-standard.md §6）。
> 用法：审核时先查本表拿到门槛值，再取证据比对；表中未收录的条目，按「机制 + 覆盖范围 + 失效场景」自行补一条合格线，写进报告。
> 标 **P0** 的为阻断项：未达线即不可上线，不接受「后续优化」。

## A. 脱敏与隐私

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| A-01/02 | 覆盖 7 类字段（手机、证件、卡号、邮箱、地址、姓名、IP）；统一在序列化层实现，手写脱敏点 = 0 | 脱敏注解/序列化器代码 + 全局配置 | 各接口各自 `replaceAll`，漏一处即泄露 |
| A-03 | 列表页 / 详情页 / 导出 / 打印 / 开放 API **五处规则一致**，抽查 3 个字段结果相同 | 五处响应样本对比 | 导出 Excel 是明文 |
| A-04 | 抽 1 万行生产/预发日志，敏感值命中 **0** | `grep` 日志样本 | 请求体整体打印、SQL 参数日志含手机号 |
| A-05 | AES-256-GCM + HMAC-SHA256 盲索引；`key_version` 字段存在；密钥不在应用库内 | 表结构 + 密钥托管位置 | 密钥明文存同库配置表（反例 #11） |
| A-06 | 明文查看需二次授权 + 审计记录（谁、何时、看了谁的、几条） | 审计日志样本 | 只要登录就能看 |
| A-07 | 接口响应体为脱敏值，前端无需处理 | 直接 curl 原始响应 | 下发明文靠前端遮挡（反例 #4） |
| A-09 | 导出文件带下载者标识/水印；单次导出 ≤ 1 万行，超限走审批 | 导出实现 + 限制配置 | 无上限、无水印 |

## B. 认证与授权

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| B-01 **P0** | 权限点覆盖率 = **100%**（有权限注解的接口 / 全部非公开接口）；白名单逐条列出并说明理由 | 接口清单 vs 注解统计脚本 | 类级注解下方法 `permitAll`（反例 #3） |
| B-02 **P0** | 每个涉资源的查询/更新都带归属条件；水平越权用例 ≥ 10 条全部拦截 | 越权测试报告 | 列表接口按 ID 过滤，详情接口忘了 |
| B-03 **P0** | 普通用户直调管理端接口 100% 返回 403 | 越权矩阵测试（未登录/普通/管理员 × 敏感接口） | 前端隐藏按钮当权限 |
| B-04 | Access ≤ 2h、Refresh ≤ 7d；踢下线 ≤ 5s 生效 | Token 配置 + 实测 | 只靠前端删 token |
| B-05 **P0** | BCrypt cost ≥ 10（建议 12）或 Argon2id（m=19MiB, t=2, p=1）；MD5/SHA1/明文 = 0 命中 | 全仓密码处理代码 | 老数据 MD5 未迁移 |
| B-06 | 连续失败 5 次锁定 15 min；短信 1 条/60s/号、5 条/天/号 | 限流配置 + 实测 | 只按 IP（反例 #7） |
| B-09 **P0** | 无默认超管口令；演示账号 = 0；首登强制改密 | 账号表 + 登录流程 | `admin/123456` 残留 |
| B-10 | OAuth/微信回调校验 `state` + 来源域名白名单 | 回调代码 | 只换 code 不校验 state |

## D. 数据与事务

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| D-01 | 事务只在 Service 层；事务内远程调用/MQ 发送 = 0 命中 | 静态扫描 | 事务里发短信 |
| D-03 | 单事务 P99 ≤ 1s；锁等待 > 500ms 告警 | 慢事务日志 | 批量导入一个事务跑 5 分钟 |
| D-05 **P0** | 订单号、渠道流水号、幂等键三处**必须有唯一索引** | `SHOW INDEX` | 靠代码判重（反例 #2） |
| D-06 **P0** | 金额字段 DECIMAL(18,2)（费率 18,4）；`double/float` 参与金额运算 = 0 | 表结构 + 全仓扫描 | 用 double 算手续费 |
| D-07 | 逻辑删除不与唯一索引冲突（唯一索引含 `deleted` 或走归档表） | 索引定义 | 软删后同键插入失败被吞（反例 #9） |
| D-08 | 迁移脚本版本化（Flyway/Liquibase/Alembic/Prisma），可回滚，重复执行幂等 | 迁移目录 | 手工改生产表 |
| D-10 **P0** | 全量+增量备份；**近 90 天内有成功恢复演练记录**；实测 RTO 达目标 | 演练报告 + 实测值 | 只有备份成功日志（反例 #5） |

## E. 索引与 SQL 性能

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| E-01 **P0** | 核心查询 `EXPLAIN` type ≤ `range`，`type=ALL` = 0 | EXPLAIN 输出 | 有索引但被函数包住（反例 #8） |
| E-02/03 | 索引列无函数/运算、无前导模糊、无隐式类型转换 | EXPLAIN 的 key 与 rows | `WHERE DATE(t)=...` |
| E-04 | 高频查询实现覆盖索引（`Extra: Using index`）；回表率可解释 | EXPLAIN | 全字段回表 |
| E-06 | 深分页改游标或延迟关联；`LIMIT > 10000` 的 offset = 0 | SQL 审查 | `limit 100000,20` |
| E-08 | 慢查询阈值 1s 开启；慢 SQL 待办闭环 ≤ 7 天 | 慢日志 + 待办表 | 开了日志没人看 |
| E-09 | 批量写 500–1000/批；单事务写 10 万行 = 0 | 代码 + 事务日志 | 一次性 insert 全量 |

## F. 幂等与并发

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| F-01 **P0** | 下单、支付回调、退款、领券、MQ 消费 5 类幂等覆盖 100%，且都有 DB 唯一键兜底 | 幂等矩阵表 + 索引 | 只有 Redis 占位（反例 #2） |

| F-03 | 锁在事务外层；粒度 = 业务主键；超时 30s + 看门狗；持有 < 1s | 锁代码 | 锁在事务内（锁先放、数据后提交） |
| F-05 **P0** | 条件更新 `where stock >= n`，affected=0 即失败；并发用例 200 线程 × 100 库存，**超卖 = 0** | 并发测试报告 | 先查后改（反例 #1 同类） |
| F-06 | 状态机每步校验前置状态；重复退款/重复发货用例拦截率 100% | 状态流转代码 + 用例 | 只判断 `status != 成功` |

## G. 缓存

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| G-01 | 穿透：空值缓存 30–60s 或布隆过滤器；击穿：互斥重建或逻辑过期；雪崩：TTL ±10% 抖动 | 缓存代码 | 三项只做一项 |
| G-02 | 一致性策略明确（Cache Aside / 延迟双删 / binlog），**顺序必须是先写库后删缓存** | 代码顺序 | 先删缓存再写库（反例 #14） |
| G-03 | 大 key（>10KB 或成员数 > 5000）= 0；热 key 有本地缓存或拆 key | `--bigkeys` 输出 | 缓存整个列表页 |
| G-04 | key 规范 `业务:实体:id:版本`；无 TTL 的 key = 0（除明确声明的常驻） | key 清单 | 永不过期且无失效逻辑 |
| G-05 | `maxmemory` 已配；策略非 `noeviction` | `CONFIG GET` | 默认 noeviction 导致写失败 |

## H. 稳定性与容错

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| H-01 **P0** | 超时阶梯：网关 10s > 服务 5s > DB 2s > Redis 200ms；**下游 < 上游**，链路累加 ≤ 用户可接受等待 | 各层配置值 | 每层都 30s，链路 60s（反例 #1） |
| H-02 | 第三方调用：重试 ≤ 3 次（退避 200ms/1s/5s + ±20% 抖动）+ 熔断（失败率 50%、最小请求 20、窗口 10s、半开 3 次）+ 降级返回 | 客户端配置 | 配了组件但阈值永不触发（反例 #6） |
| H-04 **P0** | 登录 5/min/IP + 10/h/账号；导出 3/h/用户；支付 10/min/用户；短信见 B-06 | 限流规则 | 单维度限流（反例 #7） |
| H-05 | 线程池按依赖隔离；队列有界（≤ 1000）；拒绝策略非静默丢弃 | 线程池配置 | 共用 `ForkJoinPool.commonPool` |
| H-07 | liveness / readiness 分离；readiness 检查 DB + Redis，超时 ≤ 2s | 探针配置 | 两者同一个接口 |
| H-08 | 优雅停机：先摘流量 → 等在途 ≤ 30s → 关资源；实测 SIGTERM 后 5xx = 0 | 停机日志 | 直接 kill 丢请求 |
