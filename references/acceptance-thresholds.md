# 合格线阈值表（把「是否」变成「对不对」）

> 配套 `verification-standard.md` 使用。本表为**常见行业基线**，不是唯一正确答案。
> 项目可调，但必须书面声明调整项、调整理由与签字人（规则见 verification-standard.md §6）。
> 用法：审核时先查本表拿到门槛值，再取证据比对；表中未收录的条目，按「机制 + 覆盖范围 + 失效场景」自行补一条合格线，写进报告。
> 标 **P0** 的为阻断项：未达线即不可上线，不接受「后续优化」。

## A. 脱敏与隐私

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| A-01/02 | 覆盖 7 类字段（手机、证件、卡号、邮箱、地址、姓名、IP）；统一在序列化层实现，手写脱敏点 = 0 | 脱敏注解/序列化器代码 + 全局配置 | 各接口各自 `replaceAll`，漏一处即泄露 |
| A-03 | 列表页 / 详情页 / 导出 / 打印 / 开放 API **五处规则一致**，抽查 3 个字段结果相同 | 五处响应样本对比 | 导出 Excel 是明文 |
| A-04 | 抽 1 万行生产/预发日志，敏感值命中 **0** | `grep` 日志样本 | 请求体整体打印、SQL 参数日志含手机号 |
| A-05 | AES-256-GCM + HMAC-SHA256 盲索引；`key_version` 字段存在；密钥不在应用库内 | 表结构 + 密钥托管位置 | 密钥明文存同库配置表（反例 #11） |
| A-06 | 明文查看需二次授权 + 审计记录（谁、何时、看了谁的、几条） | 审计日志样本 | 只要登录就能看 |
| A-07 | 接口响应体为脱敏值，前端无需处理 | 直接 curl 原始响应 | 下发明文靠前端遮挡（反例 #4） |
| A-09 | 导出文件带下载者标识/水印；单次导出 ≤ 1 万行，超限走审批 | 导出实现 + 限制配置 | 无上限、无水印 |

## E. 索引与 SQL 性能

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| E-01 **P0** | 核心查询 `EXPLAIN` type ≤ `range`，`type=ALL` = 0 | EXPLAIN 输出 | 有索引但被函数包住（反例 #8） |
| E-02/03 | 索引列无函数/运算、无前导模糊、无隐式类型转换 | EXPLAIN 的 key 与 rows | `WHERE DATE(t)=...` |

| E-06 | 深分页改游标或延迟关联；`LIMIT > 10000` 的 offset = 0 | SQL 审查 | `limit 100000,20` |
| E-08 | 慢查询阈值 1s 开启；慢 SQL 待办闭环 ≤ 7 天 | 慢日志 + 待办表 | 开了日志没人看 |
| E-09 | 批量写 500–1000/批；单事务写 10 万行 = 0 | 代码 + 事务日志 | 一次性 insert 全量 |

## G. 缓存

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |

## H. 稳定性与容错

| ID | 合格线 | 证据 | 典型不合格 |
| --- | --- | --- | --- |
| H-01 **P0** | 超时阶梯：网关 10s > 服务 5s > DB 2s > Redis 200ms；**下游 < 上游**，链路累加 ≤ 用户可接受等待 | 各层配置值 | 每层都 30s，链路 60s（反例 #1） |
| H-02 | 第三方调用：重试 ≤ 3 次（退避 200ms/1s/5s + ±20% 抖动）+ 熔断（失败率 50%、最小请求 20、窗口 10s、半开 3 次）+ 降级返回 | 客户端配置 | 配了组件但阈值永不触发（反例 #6） |
| H-04 **P0** | 登录 5/min/IP + 10/h/账号；导出 3/h/用户；支付 10/min/用户；短信见 B-06 | 限流规则 | 单维度限流（反例 #7） |
| H-05 | 线程池按依赖隔离；队列有界（≤ 1000）；拒绝策略非静默丢弃 | 线程池配置 | 共用 `ForkJoinPool.commonPool` |
| H-07 | liveness / readiness 分离；readiness 检查 DB + Redis，超时 ≤ 2s | 探针配置 | 两者同一个接口 |
| H-08 | 优雅停机：先摘流量 → 等在途 ≤ 30s → 关资源；实测 SIGTERM 后 5xx = 0 | 停机日志 | 直接 kill 丢请求 |

## 未收录条目的处理

本表未覆盖的条目（Part 2 攻击面 44 条、Part 3 语言专项 58 条、Part 4 中间件 42 条，以及 Part 1 中偏定性的条目），按以下格式在现场补一条合格线，写进报告附录：

```
ID：<原编号>
判定对象：<找什么>
合格线：<可量化或可枚举的判据>（依据：<文档/标准/实测基线>）
证据：<文件:行号 / 命令 / 输出>
反例：<什么样的实现看起来有但无效>
```

写不出合格线的条目，判定时必须标「待验证」并说明原因，**不得默认通过**。
