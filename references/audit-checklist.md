# 生产级审核清单（Audit Checklist）

> 用途：对**已有项目**做生产级审核，或对**本技能产出的项目**做交付前复核。
> 判定三态：`通过` / `不通过` / `不适用（须给理由）`。
> 每条结论必须带**证据**：`文件:行号` / 接口路径 / 配置项名 / SQL / 命令输出。禁止只写「已检查」。
> 分级：**阻断 P0**（安全、资金、数据丢失、不可上线）/ **建议 P1**（影响稳定性与可维护性）/ **记录 P2**（规模化前提）。

---

## Part 1 · 通用生产级审核（A–X，24 组）

### A. 脱敏与隐私
- [ ] 是否对脱敏字段处理：手机号、身份证、银行卡、邮箱、详细地址、真实姓名、IP、设备号
- [ ] 脱敏是否在序列化层统一实现（Jackson Serializer / Pydantic field_serializer / class-transformer），而非各接口手写
- [ ] 列表页、详情页、导出 Excel/CSV、打印页、开放 API 五处规则是否一致
- [ ] 日志是否出现完整敏感值（请求体打印、异常堆栈、SQL 参数日志、MQ 消费日志、审计日志）
- [ ] 加密字段是否密文入库 + 盲索引查询，密钥外置，是否支持密钥版本轮换
- [ ] 管理端查看完整值是否二次授权 + 审计留痕
- [ ] 前端是否只渲染后端脱敏结果，而非下发明文后前端遮挡
- [ ] 第三方回调、对账文件、消息推送、短信模板中是否夹带明文
- [ ] 导出文件是否加水印/下载者标识，是否限次限量
- [ ] 测试环境与日志平台的数据是否同样脱敏（生产数据回灌开发是常见违规点）

### B. 认证与授权
- [ ] 每个接口是否显式声明权限点，有无「登录即可访问」的管理接口
- [ ] 是否实现数据权限（仅能访问自己的资源），是否有水平越权用例并通过
- [ ] 垂直越权：普通用户直接调管理端接口是否被拦
- [ ] Token 签发、过期、续期、主动失效（踢下线）是否落地
- [ ] 密码存储是否 BCrypt(cost≥10)/Argon2，是否残留 MD5/SHA1/明文/可逆加密
- [ ] 登录失败锁定、验证码、短信发送频率是否限流
- [ ] 会话固定、Cookie 属性（HttpOnly/Secure/SameSite）是否设置
- [ ] 多端登录策略、并发会话上限是否明确
- [ ] 默认超管账号是否改密或首次登录强制改密；是否存在演示账号残留
- [ ] 第三方登录（OAuth/微信）回调是否校验 state 与来源

### C. 配置与密钥
- [ ] 配置是否全部外置（环境变量/配置中心），仓库与镜像中是否残留真实密钥
- [ ] 敏感项是否无默认值，缺失即启动失败（而非静默使用空串）
- [ ] 证书、私钥、.env 是否在 .gitignore，历史提交是否清理（git log -S 检索）
- [ ] 密钥是否有轮换与吊销方案（AES/HMAC/JWT secret/数据库口令）
- [ ] 生产是否关闭 Swagger/Actuator/pprof/debug 端点或加鉴权
- [ ] 中间件端口是否只绑内网/本机，是否有 0.0.0.0 暴露风险
- [ ] 配置项是否有校验（启动时 fail-fast），是否有人改错无人知
- [ ] 配置变更是否需要重启，是否需要审批与留痕

### D. 数据与事务
- [ ] 事务是否只在 Service 层，事务内是否有远程调用或 MQ 发送
- [ ] 事务失效写法：自调用、非 public、异常被吞、非运行时异常未 rollback、多数据源未指定事务管理器
- [ ] 事务隔离级别是否明确，是否出现长事务（>1s）与锁等待
- [ ] 是否发生死锁，是否有重试与监控
- [ ] 唯一索引是否覆盖业务唯一键（订单号、支付流水、幂等键、关系表）
- [ ] 金额字段是否 DECIMAL/BigDecimal，是否存在 double/float 参与金额运算
- [ ] 逻辑删除是否与唯一索引冲突，是否用组合索引或归档表规避
- [ ] 迁移脚本是否版本化（Flyway/Liquibase/Alembic/Prisma）、可回滚、可重放
- [ ] 大表变更是否用在线 DDL 工具（gh-ost/pt-osc），是否评估锁表时间
- [ ] 备份策略（全量+增量）是否落地，是否做过真实恢复演练并记录 RTO

### E. 索引与 SQL 性能
- [ ] 核心查询是否走索引，是否被 `explain` 验证（type 不是 ALL）
- [ ] 是否存在隐式类型转换（字符串列传数字、字符集不一致导致索引失效）
- [ ] 是否在索引列上使用函数或前导模糊（`like '%x'`）
- [ ] 联合索引是否符合最左前缀，是否利用覆盖索引避免回表
- [ ] 是否出现 N+1 查询，是否用批量查询/预加载解决
- [ ] 深分页（`limit 100000,20`）是否改为游标/延迟关联
- [ ] 是否有全表 count、无索引 order by、无索引 group by
- [ ] 慢查询日志是否开启（阈值 1s），慢 SQL 是否有治理闭环
- [ ] 批量写是否分批提交（每批 500–1000），是否有单事务写十万行的写法
- [ ] 是否使用 `select *`、返回大字段（TEXT/BLOB）到列表页

### F. 幂等与并发
- [ ] 下单、支付回调、退款、领券、MQ 消费是否全部幂等，幂等键是否唯一索引兜底
- [ ] 幂等是否覆盖「请求超时后重试」「用户双击」「网关重放」三种场景
- [ ] 分布式锁是否在事务外层、粒度是否业务主键、是否设置超时与续期
- [ ] 锁失效后是否有兜底（唯一索引/状态机 CAS），是否存在「锁一失效就超卖」
- [ ] 库存/名额扣减是否条件更新（`where stock >= n`）或乐观锁，而非先查后改
- [ ] 状态机流转是否有前置状态校验（防重复退款、重复发货）
- [ ] 并发写同一行是否评估热点（计数器、库存）并做分段/队列化
- [ ] 是否有并发压测或并发用例证明，而非口头保证
- [ ] 乐观锁版本号是否随每次更新递增，是否存在丢更新
- [ ] 分布式场景是否存在「先删缓存再写库」等错序操作

### G. 缓存
- [ ] 穿透：空值缓存/布隆过滤器；击穿：互斥重建/逻辑过期；雪崩：TTL 抖动——三者是否分别有对策
- [ ] 缓存一致性策略是否明确（Cache Aside / 延迟双删 / binlog 订阅）
- [ ] 是否有大 key（>10KB 或成员数万）、热 key（单 key QPS 过高）
- [ ] key 命名规范是否统一（业务:实体:id:版本），是否设置过期时间
- [ ] 内存淘汰策略（maxmemory-policy）是否与业务匹配
- [ ] 缓存击穿时的降级返回是否合理（不返回脏数据）
- [ ] 缓存与 DB 双写失败是否有补偿
- [ ] 预热方案是否存在（大促/发版后冷启动）
- [ ] 本地缓存（Caffeine）与分布式缓存的一致性是否说明

### H. 稳定性与容错
- [ ] 所有 HTTP/DB/Redis/MQ 客户端是否显式设置连接、读、写超时
- [ ] 第三方调用是否有限重试（含退避与抖动）、熔断、降级
- [ ] 重试是否会在故障时放大流量（是否与限流、熔断配合）
- [ ] 登录、短信、导出、支付接口是否按 IP/用户/全局三档限流
- [ ] 线程池是否按依赖隔离、队列有界、拒绝策略明确
- [ ] 是否存在共用默认线程池（ForkJoinPool.commonPool / 全局 executor）
- [ ] liveness/readiness 是否分离，readiness 是否检查 DB/Redis 依赖
- [ ] 是否优雅停机（先摘流量 → 等在途请求 → 关闭资源）
- [ ] 定时任务是否防多实例重复执行（分布式调度或锁）
- [ ] 启动是否幂等（重复启动不重复初始化数据），是否有启动依赖顺序问题

### I. 消息队列
- [ ] 生产者是否开启 confirm/ack，是否处理发送失败与本地消息表补偿
- [ ] 消费是否幂等（业务唯一键 + 去重表/状态机）
- [ ] 消息是否会丢：持久化、手动 ack、消费异常重试策略是否明确
- [ ] 重试次数与间隔、死信队列、人工补偿入口是否存在
- [ ] 顺序消息是否按业务键分区，是否真的需要顺序
- [ ] 积压监控与扩容方案是否存在（消费速率 > 生产速率）
- [ ] 消息体是否过大（>1MB），是否传 ID 而非全量对象
- [ ] 延迟消息/定时消息的实现方式是否可靠
- [ ] 事务消息或最终一致方案是否写清（订单+库存+积分）

### J. 定时任务与调度
- [ ] 任务是否幂等可重跑，失败是否可续跑
- [ ] 多实例是否只执行一次（分布式锁/调度中心）
- [ ] 执行时长是否超预期，是否有超时中断与告警
- [ ] 任务失败是否有告警与重试，是否有任务执行记录表
- [ ] 大批量任务是否分片/分批，是否影响在线流量（错峰）

### K. 支付与资金
- [ ] 支付回调是否验签、验金额、验商户号，是否拒绝重复与伪造
- [ ] 回调是否幂等，是否以「渠道流水号」为唯一键
- [ ] 回调与主动查单是否双保险（回调丢失可补偿）
- [ ] 金额计算是否全链路整数分或 BigDecimal，是否有精度丢失
- [ ] 是否有时对账（渠道账单 vs 本地流水），差异处理流程是否明确
- [ ] 退款是否校验可退金额、是否防重复退款、是否原路退回
- [ ] 资金流水是否只增不改，是否有账务平衡校验
- [ ] 优惠券/积分核销是否原子（防超发、防重复核销）
- [ ] 支付渠道密钥是否分环境隔离，是否支持多商户
- [ ] 是否有资损监控与熔断（异常订单量、异常退款量告警）

### L. 文件与对象存储
- [ ] 上传是否白名单校验类型（MIME + 魔数），是否限制大小
- [ ] 是否重命名落盘、禁止按原文件名与用户路径拼接
- [ ] 私有桶 + 预签名访问，链接有效期是否合理，是否可被枚举
- [ ] 是否存在路径穿越（`../`）、双扩展名、SVG/HTML 内嵌脚本 XSS
- [ ] 图片是否做压缩/尺寸限制，是否剥离 EXIF
- [ ] 大文件是否分片上传、断点续传、秒传（hash 去重）
- [ ] 是否做病毒扫描或至少隔离区，是否禁止上传目录可执行
- [ ] 删除是否软删 + 延迟清理，是否有孤儿文件清理任务

### M. 可观测性
- [ ] 日志是否结构化，traceId 是否贯穿入口→DB→下游
- [ ] 是否存在 printStackTrace、无上下文日志、循环内海量日志
- [ ] 日志级别是否合理（生产 INFO 起步，无 DEBUG 泛滥）
- [ ] 指标是否采集：QPS、P99、错误率、连接池、队列积压、JVM/运行时、GC
- [ ] 告警是否有负责人、阈值依据、处置手册，是否避免告警风暴
- [ ] 是否有链路追踪（跨服务），是否采样率合理
- [ ] 关键业务埋点是否可回答「今天下了多少单、失败在哪一步」
- [ ] 日志轮转与磁盘水位是否受控（避免磁盘打满导致宕机）
- [ ] 是否可在 5 分钟内定位一次线上故障（有无排障入口与手册）

### N. 审计与合规
- [ ] 审计日志是否覆盖：登录、权限变更、资金操作、数据导出、敏感数据查看
- [ ] 审计日志是否独立存储、只追加、不可篡改、可检索
- [ ] 日志保留期是否满足（≥30 天；等保场景 ≥6 个月）
- [ ] 个人信息是否最小化收集，是否有授权记录、导出与删除能力
- [ ] 是否支持账号注销与数据删除（含备份中的处理说明）
- [ ] 是否有等保/密评要求的双因子、漏洞扫描、角色分离
- [ ] 数据出境与存储地域是否有说明
- [ ] 隐私政策/用户协议与实际采集项是否一致

### O. 接口契约与 API 文档（要求实时更新）
- [ ] 文档是否与代码同源（springdoc/FastAPI/swaggo/@nestjs/swagger），而非手写 Word
- [ ] 实际响应与文档是否一致（字段名、类型、可空性、分页结构、错误码）
- [ ] 统一响应体 `{code,message,data,traceId}` 是否全站贯彻，有无裸返回
- [ ] 错误码表是否与代码枚举一致，是否存在未登记/已废弃未删除的错误码
- [ ] 字段规范是否写明：时间格式与时区、金额单位、ID 是否字符串化、枚举取值全列
- [ ] 鉴权 Header、`Idempotency-Key`、`X-Request-Id`、401/403 语义是否写入文档
- [ ] 版本策略（`/api/v1`）、破坏性变更的兼容窗口与下线时间
- [ ] 文档是否可导出 OpenAPI 并成功导入 Apifox/Postman（无解析报错）
- [ ] **本次改动涉及的新增/变更/废弃接口是否已当场更新文档**
- [ ] 文档示例值是否可真实调通（非 `xxx` 占位），是否区分 dev/test/prod baseURL

### P. 方案书一致性（要求实时更新）
- [ ] 实现是否偏离方案书对应章节，偏差是否登记（含原因与影响面）
- [ ] 新增的表、索引、中间件、依赖、第三方服务是否回写方案书
- [ ] 容量估算、连接池、限流阈值、超时值是否与线上实际一致
- [ ] 「不做的事 / P2 延后项」是否仍标注清楚，有无被悄悄降级
- [ ] 架构图与模块边界是否与代码结构一致（目录、依赖方向）
- [ ] 变更记录是否更新（版本号 + 日期 + 变更点 + 影响面 + 回滚方式）
- [ ] 双向偏差是否都查：代码做了方案没写 / 方案写了代码没做

### Q. 部署与环境
- [ ] dev/test/prod 是否库、中间件、凭据三隔离，是否共用同一实例
- [ ] 镜像是否多阶段构建、非 root、带 healthcheck、基础镜像版本固定
- [ ] 是否有 CI（构建→单测→镜像→部署）与可回滚的镜像 tag 策略
- [ ] DDL 与应用发布是否解耦（先兼容旧版本，再删旧字段）
- [ ] 时区（TZ）、字符集（utf8mb4）、连接串参数是否全环境统一
- [ ] 环境变量是否有清单与校验，是否有人靠记忆手工配
- [ ] 启动顺序与初始化脚本是否幂等，是否可一键起本地环境
- [ ] 资源限制（CPU/内存/JVM 堆）是否与容量估算匹配，是否有 OOM 风险
- [ ] 日志与数据卷是否持久化，容器重建是否丢数据

### R. 发布与变更管理
- [ ] 发布是否灰度/滚动，是否有灰度指标与回滚判据
- [ ] 回滚是否演练过，回滚是否需要数据回退（不可逆变更如何处理）
- [ ] 是否有功能开关（feature flag）支持快速关停新逻辑
- [ ] 上线检查表是否包含：建库、配密钥、验回调、跑冒烟、改默认密码
- [ ] 变更是否有审批与公告，是否避开业务高峰
- [ ] 是否有人工动作清单（无法自动化但必须做的步骤）
- [ ] 事故复盘机制是否存在，action item 是否闭环

### S. 依赖与供应链
- [ ] 依赖是否有已知高危 CVE（dependency-check / npm audit / govulncheck / pip-audit）
- [ ] 版本是否锁定（lock 文件入库），是否禁止动态版本（`^`、`latest`）
- [ ] 是否禁用不可信源，是否配置私有镜像与校验
- [ ] 是否清理未使用依赖与冗余传递依赖
- [ ] 基础镜像与运行时是否定期重建（含 OS 补丁）
- [ ] 构建是否可复现（同一 commit 产出同一镜像）

### T. 代码质量与测试
- [ ] 是否有全局异常处理器，异常是否被吞、是否只打日志不回滚
- [ ] 是否有静态检查（checkstyle/spotbugs/golangci-lint/ruff/eslint）并纳入 CI
- [ ] 单测覆盖核心逻辑（金额、状态机、幂等），关键路径是否覆盖异常分支
- [ ] 是否有集成测试覆盖 DB/缓存/MQ（至少冒烟一条happy path）
- [ ] 接口是否有契约测试或自动化用例集合（可回归）
- [ ] 是否有硬编码（URL、账号、密钥、业务常量、魔法值）
- [ ] 关键路径是否残留 TODO/FIXME、注释掉的代码、调试开关
- [ ] 代码分层是否清晰（Controller 无业务、Service 无 SQL 拼接、Mapper 无业务）

### U. 性能与容量
- [ ] 是否做过压测，是否有 QPS/P99/错误率 基线数据
- [ ] 容量估算是否写明（峰值 QPS、连接数、存储增长/月、带宽）
- [ ] 数据库连接池、Redis 连接池、HTTP 连接池是否按估算配置
- [ ] 是否存在单点（单实例 DB/Redis/应用），是否接受并说明
- [ ] 是否存在慢接口（>1s）未优化，是否有缓存或异步化方案
- [ ] 大报表/导出是否异步（任务化 + 轮询/通知），是否限流
- [ ] 是否评估过 GC/内存增长，是否有内存泄漏排查手段
- [ ] 是否评估过带宽与对象存储费用（成本也是容量）

### V. 灾备与数据生命周期
- [ ] RTO/RPO 目标是否明确，是否与业务方确认

## Part 2 · 攻击面专项（逐项打勾，按 OWASP + 实战高频）

### 注入类
- [ ] SQL 注入：是否全部参数化/ORM 绑定，是否残留字符串拼接（含 `order by`、`like`、`in`）
- [ ] NoSQL 注入：Mongo 查询是否过滤 `$ne/$gt/$where` 等操作符注入

- [ ] 模板注入（SSTI）：用户输入是否进入模板编译（Thymeleaf/Freemarker/Jinja2）
- [ ] 表达式注入：SpEL/OGNL/Aviator 是否解析外部输入
- [ ] LDAP/XPath 注入（如涉及）
- [ ] 反序列化：是否反序列化不可信数据（Java 原生序列化、Fastjson autoType、Pickle、YAML unsafe_load）
- [ ] XXE：XML 解析是否禁用外部实体与 DTD
- [ ] 日志注入：用户输入含换行/控制字符是否直接落日志（可伪造日志）

### 文件与路径
- [ ] 路径穿越：文件下载/读取是否校验规范化路径（`../`、绝对路径、软链）
- [ ] 任意文件读取/删除接口是否鉴权
- [ ] 上传：双扩展名、Content-Type 伪造、魔数不校验、压缩炸弹（zip bomb）
- [ ] 上传目录是否可执行、是否可被直接 URL 访问（尤其 jsp/php/svg/html）
- [ ] 图片处理是否受 ImageTragick 类漏洞影响（老版本 ImageMagick）

### 请求与信任边界
- [ ] SSRF：所有外部 URL 抓取/回调是否限制内网地址（127.0.0.1、169.254、10/172/192 段、DNS 重绑定）
- [ ] 开放重定向：redirect 参数是否白名单
- [ ] CSRF：Cookie 会话是否校验 Origin/Referer 或 CSRF Token
- [ ] CORS：是否 `Access-Control-Allow-Origin: *` 且带凭据（严重错误）
- [ ] 点击劫持：X-Frame-Options / CSP frame-ancestors
- [ ] HTTP 参数污染、Host 头注入（密码重置链接）、X-Forwarded-For 伪造绕过限流
- [ ] 请求走私（前后端 Content-Length/Transfer-Encoding 不一致）
- [ ] Webhook 接收是否验签 + 时间戳 + 防重放

### 鉴权与令牌
- [ ] JWT：是否校验 alg（防 none/RS256→HS256 混淆）、是否校验 exp/iat/aud/iss
- [ ] JWT 密钥是否弱口令或与示例一致；是否可被枚举爆破
- [ ] 签名是否防重放（nonce + timestamp + 一次性缓存）
- [ ] 敏感比较是否常量时间（防时序攻击）
- [ ] IDOR：资源 ID 是否可遍历（自增 ID + 无归属校验）
- [ ] 批量赋值（Mass Assignment）：请求体是否可直接绑定实体（含 isAdmin、balance 字段）
- [ ] 越权矩阵是否测过：未登录/普通用户/管理员 × 每个敏感接口

### 信息泄露与配置
- [ ] 生产是否暴露堆栈、SQL 报错、框架版本、内部 IP
- [ ] 是否暴露 `.git`、`.env`、`backup.zip`、`phpinfo`、`actuator/env`、`/debug`、`/metrics`
- [ ] 前端 sourcemap 是否上传生产（泄露源码）
- [ ] 目录列举是否关闭；错误页是否定制
- [ ] 云存储桶是否公开可列（OSS/S3 bucket policy）
- [ ] 是否有测试后门接口、万能验证码、固定短信码
- [ ] GraphQL：是否限制查询深度/复杂度/批量别名攻击；生产是否关闭 introspection
- [ ] 限流是否可按用户维度绕过（换 IP、换 token、换手机号）

### 业务安全
- [ ] 短信/邮件轰炸防护（手机号+IP+设备三维限流）
- [ ] 验证码是否一次性、有失效时间、服务端校验
- [ ] 优惠券/积分/余额是否有并发刷取测试
- [ ] 价格与数量是否服务端重算（前端传价格是经典漏洞）
- [ ] 越权导出、批量爬取（分页无上限、导出无限制）
- [ ] 账号枚举（登录/注册/找回密码的错误信息是否一致）
- [ ] 风控：注册、登录、支付是否有基础反欺诈策略

## Part 6 · 判定规则

1. **不适用必须写理由**，例如「纯内网工具，无第三方回调 → 支付对账不适用」，一句话即可，不能留空。
2. **无法验证的项标「待验证」**，不臆断为通过；列入报告最后一段。
3. **阻断项定义**：涉及资金错误、数据丢失、可被未授权访问、密钥泄露、不可回滚的发布。
4. **只建议不代改**：审核模式默认只出报告，不动用户代码；用户明确要求后才进入整改。
5. **实时同步**：审核中发现实现与文档/方案不一致时，先记录偏差，再按用户选择更新 API 文档与方案书对应章节，并在变更记录留痕。
