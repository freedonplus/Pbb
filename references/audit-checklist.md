# 生产级审核清单（Audit Checklist）

> 用途：对**已有项目**做生产级审核，或对**本技能产出的项目**做交付前复核。
> **编号稳定**：每条有唯一 ID（A-01 风格），跨报告、跨版本引用同一缺陷必须用 ID，禁止用序号。
> **判定四态**：`通过` / `部分通过` / `不通过` / `待验证`；整组不适用时写「不适用 + 一句理由」，逐条不适用并入该组理由。
> 每条结论必须带**证据**：`文件:行号` / 接口路径 / 配置项名 / SQL / 命令输出。禁止只写「已检查」。
> **证据分层**：每条按其性质标注可验证方式——`S` 静态可查（代码/配置/文档）、`R` 需运行环境（起服务/连库/看日志）、`P` 需生产权限（压测/监控/演练）。静态审核只能闭环 S 类，R/P 类一律「待验证」并写清需要什么访问。
> 分级：**阻断 P0**（安全、资金与资损、数据丢失、合规违规、无备份单点、不可回滚发布）/ **建议 P1**（影响稳定性与可维护性）/ **记录 P2**（规模化前提）。
> **去重规则**：同一缺陷命中多条目时，只计入最具体的一条，其余标「见 <ID>」，报告按 ID 计数。
> **边界声明**：本清单产出的是静态代码审核结果，不是渗透测试，不构成对安全性与可用性的保证。
> 全量：384 条 / 50 组（Part1 A–AD 30 组 + Part2 6 组 + Part3 8 组 + Part4 6 组）。AI 辅助编码项目必须加载 `security-assurance.md`，AA/AB/AC/AD 不得整组跳过。

## Part 0 · 结构性扫描手册（大仓库先扫后读）

超过 200 个源文件的仓库，禁止逐文件通读。先用 grep/全局搜索跑下列结构性证据，再对疑点定点读文件：

| 目的 | 模式（按语言调整） |
| --- | --- |
| SQL 注入面 | `${`、`#{}` 外的拼接、`" + ` 出现在 SQL 上下文、Statement（非 Prepared） |
| 定时任务缺失 | `@Scheduled` / `@EnableScheduling` / xxl-job / quartz = 0 处即红旗 |
| 权限覆盖 | Controller 总数 vs `@SaCheckPermission`/`@PreAuthorize`/`[Authorize]` 注解数 |
| 金额精度 | `double|float` 出现在 amount/price/balance 字段附近 |
| 明文密钥 | `(?i)(secret|password|api[_-]?key|token)\s*[:=]\s*["'][^"']{6,}` 在 yaml/properties/.env |
| 事务内远程调用 | `@Transactional` 方法体内出现 RestTemplate/Feign/HttpClient/MQ send |
| 先查后改扣减 | `select` 后立即 `update` 同表且无 `where ... >=` 条件 |
| 异常吞噬 | `catch` 块内只有 log/printStackTrace 无 rethrow/rollback |
| 裸线程/默认池 | `new Thread`、`Executors.newFixedThreadPool`、`ForkJoinPool.commonPool` |
| 日志敏感词 | 日志语句中出现 password/secret/idCard/手机号变量 |

扫描结果决定「定点深读」的文件清单；结构性扫描本身也作为证据记入报告（如「全仓 grep `@Scheduled` = 0」）。

## Part 1 · 通用生产级审核（A–AD，30 组）

### A. 脱敏与隐私
- [ ] **A-01** 是否对脱敏字段处理：手机号、身份证、银行卡、邮箱、详细地址、真实姓名、IP、设备号
- [ ] **A-02** 脱敏是否在序列化层统一实现（Jackson Serializer / Pydantic field_serializer / class-transformer），而非各接口手写
- [ ] **A-03** 列表页、详情页、导出 Excel/CSV、打印页、开放 API 五处规则是否一致
- [ ] **A-04** 日志是否出现完整敏感值（请求体打印、异常堆栈、SQL 参数日志、MQ 消费日志、审计日志）
- [ ] **A-05** 加密字段是否密文入库 + 盲索引查询，密钥外置，是否支持密钥版本轮换
- [ ] **A-06** 管理端查看完整值是否二次授权 + 审计留痕
- [ ] **A-07** 前端是否只渲染后端脱敏结果，而非下发明文后前端遮挡
- [ ] **A-08** 第三方回调、对账文件、消息推送、短信模板中是否夹带明文
- [ ] **A-09** 导出文件是否加水印/下载者标识，是否限次限量
- [ ] **A-10** 测试环境与日志平台的数据是否同样脱敏（生产数据回灌开发是常见违规点）

### B. 认证与授权
- [ ] **B-01** 每个接口是否显式声明权限点，有无「登录即可访问」的管理接口
- [ ] **B-02** 是否实现数据权限（仅能访问自己的资源），是否有水平越权用例并通过
- [ ] **B-03** 垂直越权：普通用户直接调管理端接口是否被拦
- [ ] **B-04** Token 签发、过期、续期、主动失效（踢下线）是否落地
- [ ] **B-05** 密码存储是否 BCrypt(cost≥10)/Argon2，是否残留 MD5/SHA1/明文/可逆加密
- [ ] **B-06** 登录失败锁定、验证码、短信发送频率是否限流
- [ ] **B-07** 会话固定、Cookie 属性（HttpOnly/Secure/SameSite）是否设置
- [ ] **B-08** 多端登录策略、并发会话上限是否明确
- [ ] **B-09** 默认超管账号是否改密或首次登录强制改密；是否存在演示账号残留
- [ ] **B-10** 第三方登录（OAuth/微信）回调是否校验 state 与来源

### C. 配置与密钥
- [ ] **C-01** 配置是否全部外置（环境变量/配置中心），仓库与镜像中是否残留真实密钥
- [ ] **C-02** 敏感项是否无默认值，缺失即启动失败（而非静默使用空串）
- [ ] **C-03** 证书、私钥、.env 是否在 .gitignore，历史提交是否清理（git log -S 检索）
- [ ] **C-04** 密钥是否有轮换与吊销方案（AES/HMAC/JWT secret/数据库口令）
- [ ] **C-05** 生产是否关闭 Swagger/Actuator/pprof/debug 端点或加鉴权
- [ ] **C-06** 中间件端口是否只绑内网/本机，是否有 0.0.0.0 暴露风险
- [ ] **C-07** 配置项是否有校验（启动时 fail-fast），是否有人改错无人知
- [ ] **C-08** 配置变更是否需要重启，是否需要审批与留痕

### D. 数据与事务
- [ ] **D-01** 事务是否只在 Service 层，事务内是否有远程调用或 MQ 发送
- [ ] **D-02** 事务失效写法：自调用、非 public、异常被吞、非运行时异常未 rollback、多数据源未指定事务管理器
- [ ] **D-03** 事务隔离级别是否明确，是否出现长事务（>1s）与锁等待
- [ ] **D-04** 是否发生死锁，是否有重试与监控
- [ ] **D-05** 唯一索引是否覆盖业务唯一键（订单号、支付流水、幂等键、关系表）
- [ ] **D-06** 金额字段是否 DECIMAL/BigDecimal，是否存在 double/float 参与金额运算
- [ ] **D-07** 逻辑删除是否与唯一索引冲突，是否用组合索引或归档表规避
- [ ] **D-08** 迁移脚本是否版本化（Flyway/Liquibase/Alembic/Prisma）、可回滚、可重放
- [ ] **D-09** 大表变更是否用在线 DDL 工具（gh-ost/pt-osc），是否评估锁表时间
- [ ] **D-10** 备份策略（全量+增量）是否落地，是否做过真实恢复演练并记录 RTO

### E. 索引与 SQL 性能
- [ ] **E-01** 核心查询是否走索引，是否被 `explain` 验证（type 不是 ALL）
- [ ] **E-02** 是否存在隐式类型转换（字符串列传数字、字符集不一致导致索引失效）
- [ ] **E-03** 是否在索引列上使用函数或前导模糊（`like '%x'`）
- [ ] **E-04** 联合索引是否符合最左前缀，是否利用覆盖索引避免回表
- [ ] **E-05** 是否出现 N+1 查询，是否用批量查询/预加载解决
- [ ] **E-06** 深分页（`limit 100000,20`）是否改为游标/延迟关联
- [ ] **E-07** 是否有全表 count、无索引 order by、无索引 group by
- [ ] **E-08** 慢查询日志是否开启（阈值 1s），慢 SQL 是否有治理闭环
- [ ] **E-09** 批量写是否分批提交（每批 500–1000），是否有单事务写十万行的写法
- [ ] **E-10** 是否使用 `select *`、返回大字段（TEXT/BLOB）到列表页

### F. 幂等与并发
- [ ] **F-01** 下单、支付回调、退款、领券、MQ 消费是否全部幂等，幂等键是否唯一索引兜底
- [ ] **F-02** 幂等是否覆盖「请求超时后重试」「用户双击」「网关重放」三种场景
- [ ] **F-03** 分布式锁是否在事务外层、粒度是否业务主键、是否设置超时与续期
- [ ] **F-04** 锁失效后是否有兜底（唯一索引/状态机 CAS），是否存在「锁一失效就超卖」
- [ ] **F-05** 库存/名额扣减是否条件更新（`where stock >= n`）或乐观锁，而非先查后改
- [ ] **F-06** 状态机流转是否有前置状态校验（防重复退款、重复发货）
- [ ] **F-07** 并发写同一行是否评估热点（计数器、库存）并做分段/队列化
- [ ] **F-08** 是否有并发压测或并发用例证明，而非口头保证
- [ ] **F-09** 乐观锁版本号是否随每次更新递增，是否存在丢更新
- [ ] **F-10** 分布式场景是否存在「先删缓存再写库」等错序操作

### G. 缓存
- [ ] **G-01** 穿透：空值缓存/布隆过滤器；击穿：互斥重建/逻辑过期；雪崩：TTL 抖动——三者是否分别有对策
- [ ] **G-02** 缓存一致性策略是否明确（Cache Aside / 延迟双删 / binlog 订阅）
- [ ] **G-03** 是否有大 key（>10KB 或成员数万）、热 key（单 key QPS 过高）
- [ ] **G-04** key 命名规范是否统一（业务:实体:id:版本），是否设置过期时间
- [ ] **G-05** 内存淘汰策略（maxmemory-policy）是否与业务匹配
- [ ] **G-06** 缓存击穿时的降级返回是否合理（不返回脏数据）
- [ ] **G-07** 缓存与 DB 双写失败是否有补偿
- [ ] **G-08** 预热方案是否存在（大促/发版后冷启动）
- [ ] **G-09** 本地缓存（Caffeine）与分布式缓存的一致性是否说明

### H. 稳定性与容错
- [ ] **H-01** 所有 HTTP/DB/Redis/MQ 客户端是否显式设置连接、读、写超时
- [ ] **H-02** 第三方调用是否有限重试（含退避与抖动）、熔断、降级
- [ ] **H-03** 重试是否会在故障时放大流量（是否与限流、熔断配合）
- [ ] **H-04** 登录、短信、导出、支付接口是否按 IP/用户/全局三档限流
- [ ] **H-05** 线程池是否按依赖隔离、队列有界、拒绝策略明确
- [ ] **H-06** 是否存在共用默认线程池（ForkJoinPool.commonPool / 全局 executor）
- [ ] **H-07** liveness/readiness 是否分离，readiness 是否检查 DB/Redis 依赖
- [ ] **H-08** 是否优雅停机（先摘流量 → 等在途请求 → 关闭资源）
- [ ] **H-09** 定时任务是否防多实例重复执行（分布式调度或锁）
- [ ] **H-10** 启动是否幂等（重复启动不重复初始化数据），是否有启动依赖顺序问题

### I. 消息队列
- [ ] **I-01** 生产者是否开启 confirm/ack，是否处理发送失败与本地消息表补偿
- [ ] **I-02** 消费是否幂等（业务唯一键 + 去重表/状态机）
- [ ] **I-03** 消息是否会丢：持久化、手动 ack、消费异常重试策略是否明确
- [ ] **I-04** 重试次数与间隔、死信队列、人工补偿入口是否存在
- [ ] **I-05** 顺序消息是否按业务键分区，是否真的需要顺序
- [ ] **I-06** 积压监控与扩容方案是否存在（消费速率 > 生产速率）
- [ ] **I-07** 消息体是否过大（>1MB），是否传 ID 而非全量对象
- [ ] **I-08** 延迟消息/定时消息的实现方式是否可靠
- [ ] **I-09** 事务消息或最终一致方案是否写清（订单+库存+积分）

### J. 定时任务与调度
- [ ] **J-01** 任务是否幂等可重跑，失败是否可续跑
- [ ] **J-02** 多实例是否只执行一次（分布式锁/调度中心）
- [ ] **J-03** 执行时长是否超预期，是否有超时中断与告警
- [ ] **J-04** 任务失败是否有告警与重试，是否有任务执行记录表
- [ ] **J-05** 大批量任务是否分片/分批，是否影响在线流量（错峰）

### K. 支付与资金
- [ ] **K-01** 支付回调是否验签、验金额、验商户号，是否拒绝重复与伪造
- [ ] **K-02** 回调是否幂等，是否以「渠道流水号」为唯一键
- [ ] **K-03** 回调与主动查单是否双保险（回调丢失可补偿）
- [ ] **K-04** 金额计算是否全链路整数分或 BigDecimal，是否有精度丢失
- [ ] **K-05** 是否有时对账（渠道账单 vs 本地流水），差异处理流程是否明确
- [ ] **K-06** 退款是否校验可退金额、是否防重复退款、是否原路退回
- [ ] **K-07** 资金流水是否只增不改，是否有账务平衡校验
- [ ] **K-08** 优惠券/积分核销是否原子（防超发、防重复核销）
- [ ] **K-09** 支付渠道密钥是否分环境隔离，是否支持多商户
- [ ] **K-10** 是否有资损监控与熔断（异常订单量、异常退款量告警）

### L. 文件与对象存储
- [ ] **L-01** 上传是否白名单校验类型（MIME + 魔数），是否限制大小
- [ ] **L-02** 是否重命名落盘、禁止按原文件名与用户路径拼接
- [ ] **L-03** 私有桶 + 预签名访问，链接有效期是否合理，是否可被枚举
- [ ] **L-04** 是否存在路径穿越（`../`）、双扩展名、SVG/HTML 内嵌脚本 XSS
- [ ] **L-05** 图片是否做压缩/尺寸限制，是否剥离 EXIF
- [ ] **L-06** 大文件是否分片上传、断点续传、秒传（hash 去重）
- [ ] **L-07** 是否做病毒扫描或至少隔离区，是否禁止上传目录可执行
- [ ] **L-08** 删除是否软删 + 延迟清理，是否有孤儿文件清理任务

### M. 可观测性
- [ ] **M-01** 日志是否结构化，traceId 是否贯穿入口→DB→下游
- [ ] **M-02** 是否存在 printStackTrace、无上下文日志、循环内海量日志
- [ ] **M-03** 日志级别是否合理（生产 INFO 起步，无 DEBUG 泛滥）
- [ ] **M-04** 指标是否采集：QPS、P99、错误率、连接池、队列积压、JVM/运行时、GC
- [ ] **M-05** 告警是否有负责人、阈值依据、处置手册，是否避免告警风暴
- [ ] **M-06** 是否有链路追踪（跨服务），是否采样率合理
- [ ] **M-07** 关键业务埋点是否可回答「今天下了多少单、失败在哪一步」
- [ ] **M-08** 日志轮转与磁盘水位是否受控（避免磁盘打满导致宕机）
- [ ] **M-09** 是否可在 5 分钟内定位一次线上故障（有无排障入口与手册）

### N. 审计与合规
- [ ] **N-01** 审计日志是否覆盖：登录、权限变更、资金操作、数据导出、敏感数据查看
- [ ] **N-02** 审计日志是否独立存储、只追加、不可篡改、可检索
- [ ] **N-03** 日志保留期是否满足（≥30 天；等保场景 ≥6 个月）
- [ ] **N-04** 个人信息是否最小化收集，是否有授权记录、导出与删除能力
- [ ] **N-05** 是否支持账号注销与数据删除（含备份中的处理说明）
- [ ] **N-06** 是否有等保/密评要求的双因子、漏洞扫描、角色分离
- [ ] **N-07** 数据出境与存储地域是否有说明
- [ ] **N-08** 隐私政策/用户协议与实际采集项是否一致

### O. 接口契约与 API 文档（要求实时更新）
- [ ] **O-01** 文档是否与代码同源（springdoc/FastAPI/swaggo/@nestjs/swagger），而非手写 Word
- [ ] **O-02** 实际响应与文档是否一致（字段名、类型、可空性、分页结构、错误码）
- [ ] **O-03** 统一响应体 `{code,message,data,traceId}` 是否全站贯彻，有无裸返回
- [ ] **O-04** 错误码表是否与代码枚举一致，是否存在未登记/已废弃未删除的错误码
- [ ] **O-05** 字段规范是否写明：时间格式与时区、金额单位、ID 是否字符串化、枚举取值全列
- [ ] **O-06** 鉴权 Header、`Idempotency-Key`、`X-Request-Id`、401/403 语义是否写入文档
- [ ] **O-07** 版本策略（`/api/v1`）、破坏性变更的兼容窗口与下线时间
- [ ] **O-08** 文档是否可导出 OpenAPI 并成功导入 Apifox/Postman（无解析报错）
- [ ] **O-09** **本次改动涉及的新增/变更/废弃接口是否已当场更新文档**
- [ ] **O-10** 文档示例值是否可真实调通（非 `xxx` 占位），是否区分 dev/test/prod baseURL

### P. 方案书一致性（要求实时更新）
- [ ] **P-01** 实现是否偏离方案书对应章节，偏差是否登记（含原因与影响面）
- [ ] **P-02** 新增的表、索引、中间件、依赖、第三方服务是否回写方案书
- [ ] **P-03** 容量估算、连接池、限流阈值、超时值是否与线上实际一致

## Part 2 · 攻击面专项（逐项打勾，按 OWASP + 实战高频）

### 注入类
- [ ] **INJ-01** SQL 注入：是否全部参数化/ORM 绑定，是否残留字符串拼接（含 `order by`、`like`、`in`）
- [ ] **INJ-02** NoSQL 注入：Mongo 查询是否过滤 `$ne/$gt/$where` 等操作符注入
- [ ] **INJ-03** 命令注入：是否用 `Runtime.exec` 拼接、`child_process.exec` 拼接用户输入
- [ ] **INJ-04** 模板注入（SSTI）：用户输入是否进入模板编译（Thymeleaf/Freemarker/Jinja2）
- [ ] **INJ-05** 表达式注入：SpEL/OGNL/Aviator 是否解析外部输入
- [ ] **INJ-06** LDAP/XPath 注入（如涉及）
- [ ] **INJ-07** 反序列化：是否反序列化不可信数据（Java 原生序列化、Fastjson autoType、Pickle、YAML unsafe_load）
- [ ] **INJ-08** XXE：XML 解析是否禁用外部实体与 DTD
- [ ] **INJ-09** 日志注入：用户输入含换行/控制字符是否直接落日志（可伪造日志）

### 文件与路径
- [ ] **FILE-01** 路径穿越：文件下载/读取是否校验规范化路径（`../`、绝对路径、软链）
- [ ] **FILE-02** 任意文件读取/删除接口是否鉴权
- [ ] **FILE-03** 上传：双扩展名、Content-Type 伪造、魔数不校验、压缩炸弹（zip bomb）
- [ ] **FILE-04** 上传目录是否可执行、是否可被直接 URL 访问（尤其 jsp/php/svg/html）
- [ ] **FILE-05** 图片处理是否受 ImageTragick 类漏洞影响（老版本 ImageMagick）

### 请求与信任边界
- [ ] **REQ-01** SSRF：所有外部 URL 抓取/回调是否限制内网地址（127.0.0.1、169.254、10/172/192 段、DNS 重绑定）
- [ ] **REQ-02** 开放重定向：redirect 参数是否白名单
- [ ] **REQ-03** CSRF：Cookie 会话是否校验 Origin/Referer 或 CSRF Token
- [ ] **REQ-04** CORS：是否 `Access-Control-Allow-Origin: *` 且带凭据（严重错误）
- [ ] **REQ-05** 点击劫持：X-Frame-Options / CSP frame-ancestors
- [ ] **REQ-06** HTTP 参数污染、Host 头注入（密码重置链接）、X-Forwarded-For 伪造绕过限流
- [ ] **REQ-07** 请求走私（前后端 Content-Length/Transfer-Encoding 不一致）
- [ ] **REQ-08** Webhook 接收是否验签 + 时间戳 + 防重放

### 鉴权与令牌
- [ ] **AUTH-01** JWT：是否校验 alg（防 none/RS256→HS256 混淆）、是否校验 exp/iat/aud/iss
- [ ] **AUTH-02** JWT 密钥是否弱口令或与示例一致；是否可被枚举爆破
- [ ] **AUTH-03** 签名是否防重放（nonce + timestamp + 一次性缓存）
- [ ] **AUTH-04** 敏感比较是否常量时间（防时序攻击）
- [ ] **AUTH-05** IDOR：资源 ID 是否可遍历（自增 ID + 无归属校验）
- [ ] **AUTH-06** 批量赋值（Mass Assignment）：请求体是否可直接绑定实体（含 isAdmin、balance 字段）
- [ ] **AUTH-07** 越权矩阵是否测过：未登录/普通用户/管理员 × 每个敏感接口

### 信息泄露与配置
- [ ] **LEAK-01** 生产是否暴露堆栈、SQL 报错、框架版本、内部 IP
- [ ] **LEAK-02** 是否暴露 `.git`、`.env`、`backup.zip`、`phpinfo`、`actuator/env`、`/debug`、`/metrics`
- [ ] **LEAK-03** 前端 sourcemap 是否上传生产（泄露源码）
- [ ] **LEAK-04** 目录列举是否关闭；错误页是否定制
- [ ] **LEAK-05** 云存储桶是否公开可列（OSS/S3 bucket policy）
- [ ] **LEAK-06** 是否有测试后门接口、万能验证码、固定短信码
- [ ] **LEAK-07** GraphQL：是否限制查询深度/复杂度/批量别名攻击；生产是否关闭 introspection
- [ ] **LEAK-08** 限流是否可按用户维度绕过（换 IP、换 token、换手机号）

### 业务安全
- [ ] **BIZ-01** 短信/邮件轰炸防护（手机号+IP+设备三维限流）
- [ ] **BIZ-02** 验证码是否一次性、有失效时间、服务端校验
- [ ] **BIZ-03** 优惠券/积分/余额是否有并发刷取测试
- [ ] **BIZ-04** 价格与数量是否服务端重算（前端传价格是经典漏洞）

## Part 6 · 判定规则

1. **不适用必须写理由**，例如「纯内网工具，无第三方回调 → 支付对账不适用」，一句话即可，不能留空。
2. **无法验证的项标「待验证」**，不臆断为通过；列入报告最后一段，并注明是 R 类还是 P 类、需要什么访问。
3. **阻断项定义**：资金错误与资损、数据丢失、可被未授权访问、密钥泄露、合规违规（明文敏感数据导出等）、无备份单点、不可回滚的发布。
4. **结论门禁**（禁止自由裁量）：
   - 任一 P0 未闭环 → **不可上线**；
   - P0 全部闭环，P1 ≤ 3 条且用户书面接受遗留风险 → **有条件上线**（列出上线后限期补齐项）；
   - 其余 → **可上线**。
   - 待验证项中存在「若为否则属 P0」的，结论最高只能到「有条件上线」，并列出补验证清单。
5. **去重**：同一缺陷按 ID 只计一次；重复命中组标「见 <ID>」。
6. **只建议不代改**：审核模式默认只出报告，不动用户代码与文档；用户明确要求后才进入整改。
7. **偏差登记**：审核中发现实现与文档/方案不一致，记入报告「偏差登记」节，用户确认后再同步文档，并在变更记录留痕。
8. **人工门禁**：AI 辅助开发的 C3/C4 变更缺少独立人工签字、放行单或可执行回滚证据时，按 P0 处理；AI 自审、第二模型复审均不能替代。门禁缺失时结论不得高于「不可上线（流程阻断）」。
9. **复评**：整改完成后走 SKILL.md 阶段 5，出新版报告（v 序号递增），旧版结论与 diff 保留。
